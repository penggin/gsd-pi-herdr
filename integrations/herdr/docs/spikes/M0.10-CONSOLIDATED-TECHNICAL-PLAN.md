# M0.10 — Consolidated Technical Plan

## 1. Executive decision

`penggin/gsd-pi-herdr` will be maintained as a downstream GSD-Pi distribution with a first-class, in-tree Herdr subagent runtime.

The implementation will:

- keep `herdrdev/herdr` external and consume its public APIs;
- refactor GSD subagent execution behind one local/cmux/Herdr contract;
- preserve GSD's existing launch, orchestration, parsing, retry, isolation, and result semantics;
- run external panes through a dedicated worker runner;
- keep complete JSONL evidence while rendering only bounded human-readable activity;
- treat required observability as part of execution correctness;
- maintain an exact upstream mirror and validate semantic compatibility on every sync.

M0 found no unresolved ownership issue that blocks implementation.

## 3. Feasibility conclusions

### Herdr

Protocol 20 already exposes the required public surface:

```text
session snapshot
workspace/tab/pane identity
layout apply and pane split
process inspection
text/key input
pane output read
agent/session/metadata authority
agent release and pane close
event subscription/wait
plugin installation, actions, and panes
```

No Herdr core fork is justified for the initial runtime.

### GSD

The existing bundled subagent owns all important semantics, but local and cmux process execution are duplicated in one large extension file. The correct downstream change is an internal backend refactor, not replacement of the subagent tool.

### Packaging

Because this repository owns and builds the complete GSD source, the primary distribution uses the normal source build. The earlier standalone resource-overlay strategy is no longer needed. New built resources, workspace packages, binaries, and integration assets still require explicit package validation.

### Cmux

The existing downstream cmux fix identifies valid CLI changes, but it should not be merged directly. Its behavior will be reimplemented inside the unified backend while also removing raw JSON mirroring and unsafe fallback.

## 5. Non-negotiable invariants

### Result parity

```text
same child launch + equivalent child output
→ same GSD messages, usage, error, stop reason, session, retry, and merge meaning
```

Backend-specific IDs may differ, but GSD semantic results may not.

### No raw JSON terminal output

Raw `message_update` and token-delta records are stored and parsed, not rendered into cmux or Herdr panes.

### No ambiguous duplicate fallback

A monitored external launch has four relevant states:

```text
not attempted
known pre-launch failure
known launched
ambiguous launch
```

Only a known pre-launch failure may use an explicitly configured fallback. An ambiguous launch never triggers a second local child.

### Authority separation

```text
root GSD TUI → main pane authority
worker runner → worker pane authority
JSON child → neither root authority nor another pane's identity
```

### GSD remains authoritative

Backends execute and transport. They do not choose prompts, models, retries, sessions, isolation, merge outcomes, or task success.

## 9. Risk register after M0

| Risk | Severity | Current response |
|---|---:|---|
| semantic drift during backend extraction | high | local parity gate before external work |
| incomplete mode migration | high | explicit call-site matrix and tests |
| ambiguous external launch duplicates work | critical | launch-state model and no post-attempt fallback |
| raw JSON floods terminals | medium/high | dedicated runner and terminal-output assertion |
| wrong Herdr pane identity | high | strip/rebind managed environment, authority tests |
| parent or pane disappears | high | durable evidence, heartbeats, reconciliation |
| signal reaches shell but not child | high | process-group verification and exit evidence |
