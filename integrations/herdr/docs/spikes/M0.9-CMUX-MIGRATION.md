# M0.9 — Cmux Fix Branch Migration Decision

## 1. Scope

Evaluate the retained downstream branch:

```text
branch:  fix/cmux-split-cli
commit:  5b74d301b6d1599df5fe0a385b90a28b48492b9a
base:    c2e61def5d6d3d8c516d115a53654b229f658915
```

and decide whether it should be merged, cherry-picked, discarded, or reimplemented inside the planned unified execution backend.

## 2. Upstream state

The synchronized upstream baseline is:

```text
open-gsd/gsd-pi main
4b26a642c0121ae6161abbb6f2dc6937c78874dd
```

The 29 upstream commits between the cmux branch base and this baseline did not modify the cmux client or cmux test files. Current upstream still uses the stale command path:

```text
list-surfaces
send-surface
```

and still discovers a created split by comparing surface lists before and after `new-split`.

Therefore the original defect remains present in the synchronized baseline.

## 3. Current cmux CLI contract

The current documented cmux command surface includes:

```text
new-split
list-pane-surfaces
tree
send
send-key
```

It does not list `list-surfaces` or `send-surface` as current commands.

The split command returns the new surface reference in its output, so GSD does not need a before/after global surface diff to identify the pane it just created.

## 4. Changes in the retained branch

The existing commit does four substantive things:

1. changes `listSurfaceIds()` from `list-surfaces --json` to parsing `tree` output;
2. parses the surface returned by `new-split` directly;
3. changes text delivery from `send-surface` to `send`;
4. changes interruption from ETX through `send-surface` to `send-key ... ctrl+c`.

It also updates the fake CLI test to assert those new commands.

## 5. Valid behavior to preserve

### Direct split-result parsing

**Preserve.** It removes a race and avoids a second discovery command.

Target behavior:

```text
cmux new-split ...
→ validate successful response
→ extract exactly one returned surface ref
→ retain workspace/surface metadata for the execution handle
```

Parsing must fail clearly on zero or ambiguous multiple returned surface references.

### `send`

**Preserve.** Current command delivery uses `send --surface <id> <payload>`.

The unified cmux backend should send only a fixed worker-runner command with protected artifact paths. It should not interpolate raw task or prompt content into terminal input.

### `send-key ctrl+c`

**Preserve as the terminal-input step**, but do not treat a successful command as proof that the child stopped. The backend must verify exit evidence or process state and escalate through a stronger mechanism when available.

## 6. Behavior not carried forward unchanged

### `listSurfaceIds()` through `tree`

The retained patch changes the helper to a regex over `tree` output. This is not needed for normal split creation once `new-split` output is authoritative.

Decision:

- remove the helper from the execution-critical path;
- use `list-pane-surfaces` or structured tree output only for diagnostics/reconciliation where the exact scope is known;
- do not scan a whole workspace merely to discover a surface that `new-split` already returned.

### Direct shell pipeline launch

The branch does not change the current `bash -lc` and `tee` transport. That path still:

```text
prints raw JSON into the pane
delays parent parsing until completion
uses temporary evidence
has indirect cancellation
silently falls back to local execution
```

The unified backend will replace it rather than preserve it.

### Existing test shape

The branch improves the CLI fake but retains grid tests that duplicate the production algorithm in the test itself. Those tests do not prove `CmuxClient.createGridLayout()` behavior.

New tests must invoke production methods and cover command responses, partial layout failure, ambiguous split output, send failure, interrupt verification, raw JSON suppression, and fallback policy.

## 7. Merge decision

**Do not merge or cherry-pick `fix/cmux-split-cli` into the downstream line.**

Instead:

1. retain the branch as historical evidence;
2. cite commit `5b74d301...` while implementing M1;
3. reimplement the valid CLI changes in the new low-level cmux client/backend separation;
4. include the new behavior in the first unified-backend commit series;
5. close or archive the old branch only after replacement tests pass.

Rationale:

- the original source files will be substantially refactored;
- cherry-picking would create code that is immediately rewritten;
- the branch addresses only CLI compatibility, not the larger execution and observability defects;
- reimplementation allows better response validation and execution-handle semantics.

## 8. Target cmux layering

```text
src/resources/extensions/cmux/
  environment and preference detection
  sidebar / notification APIs
  low-level current CLI client
    newSplit()
    sendText()
    sendKey()
    listPaneSurfaces() for diagnostics

src/resources/extensions/subagent/execution/backends/cmux.ts
  worker surface allocation
  worker-runner launch
  JSONL relay / lifecycle handle
  targeted cancellation
  explicit fallback classification
```

The cmux client remains GSD-agnostic. The backend does not own orchestration or result parsing.

## 9. Required regression cases

```text
new-split response yields the exact new surface
obsolete list-surfaces is never called
obsolete send-surface is never called
send uses the target surface and expected payload
send-key uses ctrl+c
split creation failure is known pre-launch failure
send timeout after possible delivery is ambiguous, not safe local fallback
parallel grid uses production implementation
partial grid creation is explicit
worker process runs in the visible surface
raw JSON records are absent from pane output
complete JSONL still reaches GSD parser
cancel verifies final child state
session shutdown does not leave a live external worker
```

The old commit remains useful as a small reproduction-backed fix and as attribution for the corrected command names. The downstream architecture will absorb its behavior into a broader, tested refactor rather than erase its history.
