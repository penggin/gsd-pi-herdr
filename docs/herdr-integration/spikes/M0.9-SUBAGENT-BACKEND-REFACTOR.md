## 1. Current execution functions

There are two substantially separate execution pipelines in `subagent/index.ts`.

### `runSingleAgent()` — local child runtime

This function currently owns both common GSD semantics and local process mechanics:

1. resolve/validate the agent;
2. enforce `conflictsWith` against the active GSD phase;
3. compute effective thinking;
4. create the temporary system-prompt file;
5. initialize `SingleResult` and update callback;
6. call `createSubagentLaunchPlan()`;
7. record forked session file;
8. construct bundled extension args;
9. `spawn()` the GSD child directly with `shell: false`;
10. incrementally parse JSONL stdout through `processSubagentEventLine()`;
11. collect stderr;
12. track the direct child in `liveSubagentProcesses`;
13. on abort, send SIGTERM and later SIGKILL;
14. set exit state;
15. call `markMissingFinalResponse()`;
16. clean prompt artifacts.

The runtime-specific portion is primarily steps 8–13. The rest should not belong to LocalBackend.

### `runSingleAgentInCmuxSplit()` — duplicated cmux runtime

This repeats much of the same semantic setup but implements execution differently:

1. resolve agent; unknown agent falls back to `runSingleAgent()`;
2. compute effective thinking;
3. create prompt and `SingleResult` independently;
4. create a cmux-specific temporary output directory;
5. create/select a surface;
6. if surface creation fails, silently fall back to local execution;
7. build the same GSD launch plan again;
8. compose a bash pipeline inside the cmux pane;
9. mirror stderr with `tee` and **mirror raw JSON stdout with `tee`** into the terminal while writing `stdout.jsonl`;
10. wait for an `exit.code` file;
11. on abort/timeout, send Ctrl-C to the surface and return a synthetic cmux-specific error result;
12. only after completion, read the full JSONL file and feed it to `processSubagentEventLine()`;
13. call `markMissingFinalResponse()` on normal completion;
14. delete all temporary output files immediately.

This is not just a presentation adapter; it duplicates result creation, launch preparation, parsing/finalization, abort classification, and fallback policy.

## 2. Mode-to-runtime matrix today

| Operation | Current runtime selection | Isolation behavior | Important notes |
|---|---|---|---|
| `action=status` | no child | n/a | reads `SubagentRunStore` |
| `action=resume` | **Local only** | no new isolation | calls `runSingleAgent()` directly with existing fork session file |
| background single | **Local only** | supported | calls `runSingleAgent()` with no tool-call abort signal because tool already returned |
| chain | **Local only** | **`isolated` currently not applied** | each step calls `runSingleAgent()` directly |
| parallel | Local or Cmux | supported | cmux selection occurs inside `executeOnce`; one automatic retry repeats same runtime choice |
| foreground single | Local or Cmux | supported | cmux selected when `cmux.splits` is enabled |
| parallel retry | same Local/Cmux closure | isolation recreated per retry | `MAX_RETRIES = 1` |
| fresh context | supported through launch plan | independent of runtime | `--no-session` |
| fork context | supported through launch plan | independent of runtime | creates branched session file before launch |

### Consequence for Herdr

Adding `runSingleAgentInHerdrPane()` beside these functions would repeat the same design problem and would still leave resume/background/chain outside Herdr. The refactor must make backend resolution occur at the common single-child execution seam used by **every** child launch.

## 3. Existing semantic divergences found

These are important because the backend refactor should either preserve intentionally documented behavior or fix it with explicit regression tests; it must not accidentally codify the divergences as the new abstraction.

### 3.1 Phase conflict guard is local-only

`runSingleAgent()` checks an agent's `conflictsWith` against `getCurrentPhase()` before launch.

`runSingleAgentInCmuxSplit()` resolves the agent and immediately proceeds to result/launch setup. It does not perform the equivalent phase-conflict guard.

**Refactor decision:** agent existence, phase guard, effective model/thinking, prompt creation, and launch-plan construction move above the backend. All backends receive only an already-approved execution.

### 3.2 Cmux JSON parsing is post-completion, local parsing is streaming

Local stdout is parsed incrementally as JSONL arrives.

Cmux stores JSONL to a file, raw-`tee`s it to the pane, then reads/parses the whole file after exit. Therefore parent `onUpdate` behavior differs materially.

**Refactor decision:** define backend stream callbacks/sinks. Local feeds them from child pipes; external backends feed them by tailing the durable JSONL artifact. `processSubagentEventLine()` remains one shared parser above backends.

### 3.3 Cmux abort classification differs

Local abort sets `wasAborted` and throws so the outer dispatch machinery can synthesize an aborted/interrupted result from the active signal.

Cmux abort/timeout returns `exitCode = 1` and a cmux-specific stderr string without necessarily producing the same `stopReason = aborted` path.

**Refactor decision:** backend returns explicit execution evidence such as `{ exitCode, aborted, signal?, runtimeError? }`; the common runner maps this into the existing `SingleResult` semantics consistently.

### 3.4 Silent cmux-to-local fallback

Cmux falls back to local when:

- no cmux surface is created;
- command submission fails;
- unknown agent reaches the cmux helper.

For a monitoring-required Herdr runtime this is unacceptable, and it can also be ambiguous if an external launch may have succeeded.

**Refactor decision:** fallback policy is resolved before execution. An external backend that may have launched cannot trigger an invisible local duplicate.

### 3.5 `liveSubagentProcesses` only knows direct local children

`session_shutdown` calls `stopLiveSubagents()`, which tracks only direct `spawn()` children. Cmux workers are not registered in that set; their cancellation relies on the active tool signal path and cmux-specific handling.

**Refactor decision:** lifecycle cleanup targets backend execution handles through a backend/execution registry, not only `ChildProcess` objects.

### 3.6 Cmux worker output is deleted immediately

The cmux temp directory is removed in `finally`, so it is not durable evidence for crash/reconciliation scenarios.

**Refactor decision:** runtime artifacts become a deliberate contract. Local may remain pipe-only initially; Herdr uses durable artifacts. Shared semantic parsing must not depend on ephemeral cmux implementation details.

### 3.7 `isolated` is not currently applied to chain mode

The top-level `useIsolation` flag is honored in background single, parallel, and foreground single paths. The chain loop directly calls `runSingleAgent()` using the step cwd and does not create/capture/merge an isolation environment.

This appears inconsistent with the tool-level `isolated` option's broad wording, but it is pre-existing behavior.

**Refactor policy:** do not silently change this during the pure backend extraction. Add an explicit follow-up decision/test: either document chain isolation as unsupported or fix it in a separate focused downstream change after parity is established.

## 4. Parallel layout behavior today

Limits:

```text
MAX_PARALLEL_TASKS = 8
MAX_CONCURRENCY = 4
```

When cmux splits are enabled, the implementation pre-creates only:

```text
min(batchSize, MAX_CONCURRENCY)
```

surfaces.

However task indices above the pre-created array fall back to creating a fresh split by direction (`right`/`down`) when their turn eventually executes. Therefore an 8-task batch can grow beyond the four initially visible surfaces instead of reusing a bounded four-slot pool.

**Herdr design:** keep scheduling concurrency at four initially, but use four stable reusable Herdr slots for an eight-task batch. Task 5 reuses a released slot rather than creating pane 5. This makes the UI bounded without changing GSD task concurrency.

Cmux may later adopt the same generic pool contract if useful, but that is not required for the first extraction.

## 5. Launch-plan boundary

`launch.ts` is already a useful semantic boundary:

```ts
interface SubagentLaunchPlan {
  args: string[];
  env: NodeJS.ProcessEnv;
  cwd: string;
  session: SubagentSessionArgs;
}
```

It owns:

- JSON mode (`--mode json -p`);
- fresh vs forked session args;
- model and thinking override;
- tool list;
- appended system prompt;
- resolved cwd;
- `GSD_SUBAGENT_CHILD=1`;
- optional `GSD_RUNTIME_CONTRACT_ROOT` authority.

### Refactor issue in `launch.ts`

`buildShellEnvAssignments()` imports `shellEscape` from the cmux module. That makes a general launch helper depend on a runtime-specific integration.

**Refactor decision:** move shell escaping / cmux shell-env generation into CmuxBackend or a neutral shell utility. `launch.ts` should not import cmux.

## 6. Recommended refactor layers

### Layer A — dispatch/orchestration (existing tool execute)

Keeps:

- mode validation;
- project-agent confirmation;
- dispatch IDs/tracking names;
- run-store and journal telemetry;
- background policy;
- chain previous-output substitution;
- parallel concurrency/retry loop;
- isolation creation/capture/merge;
- final user-facing tool result.

### Layer B — common one-child semantic runner

New conceptual function:

```ts
runSingleAgentWithBackend(input, backend, callbacks): Promise<SingleResult>
```

Owns:

- agent lookup and phase-conflict guard;
- effective model/thinking;
- prompt temp file;
- `SingleResult` initialization;
- `emitUpdate()`;
- `createSubagentLaunchPlan()`;
- forked session-file recording;
- common `processSubagentEventLine()` calls;
- stderr accumulation;
- execution-evidence → abort/error mapping;
- `markMissingFinalResponse()`;
- prompt cleanup.

### Layer C — runtime backend

Proposed minimal contract:

```ts
interface SubagentExecutionBackend {
  readonly id: "local" | "cmux" | "herdr" | string;

  execute(input: {
    launch: SubagentLaunchPlan;
    extensionArgs: string[];
    signal?: AbortSignal;
    identity: {
      dispatchId?: string;
      childIndex?: number;
      agent: string;
      trackingName?: string;
      step?: number;
    };
    onStdoutLine(line: string): void;
    onStderr(chunk: string): void;
  }): Promise<{
    exitCode: number;
    aborted: boolean;
    runtimeError?: string;
    handle?: unknown;
    metadata?: Record<string, unknown>;
  }>;
}
```

The exact contract can evolve during M2, but it must expose stream/result evidence rather than `SingleResult` itself.

### Layer D — backend resolver/context

Resolve once per child launch from effective preferences/environment. This is critical because every operation — resume, background, chain, parallel, foreground single — must pass through the same runtime selection.

For parallel, a batch-aware optional capability can pre-allocate topology:

```ts
interface SubagentExecutionBatch {
  prepare?(count: number): Promise<void>;
  dispose?(): Promise<void>;
}
```

or the runtime context can manage a pane/surface pool separately. Do not bake cmux `directionOrSurfaceId` into the generic execute contract.

## 7. Backend-specific responsibilities

### LocalBackend

- spawn `process.execPath` + GSD bin/extension args/launch args;
- `shell: false`;
- feed stdout complete lines incrementally;
- feed stderr chunks;
- own direct child handle;
- implement normal signal termination/escalation;
- integrate with common execution registry for session shutdown.

### CmuxBackend

- use current cmux CLI surface API;
- incorporate/revalidate `fix/cmux-split-cli` instead of current stale `list-surfaces`/`send-surface` commands;
- create/reserve a surface outside semantic result code;
- run the existing GSD JSON child externally;
- capture JSONL without terminal raw-JSON `tee`;
- tail/relay JSON lines through common callback;
- return explicit abort/runtime evidence;
- never call LocalBackend itself; fallback belongs to resolver/policy before ambiguous launch.

### HerdrBackend

- verify configured Herdr capability set;
- reserve a stable worker-pane slot;
- write secure worker launch artifacts;
- invoke internal GSD worker entrypoint with Herdr CLI `pane run`;
- relay/tail JSONL and stderr evidence;
- send interrupt to the exact pane;
- return pane/tab/workspace/artifact metadata;
- retain artifacts/pane according to policy;
- never parse GSD semantic messages itself beyond presentation projection in the internal runner.

## 8. Exact call-site migration plan

### Resume

Current:

```text
action=resume -> runSingleAgent(local)
```

Target:

```text
action=resume -> resolve backend -> common single-child runner
```

Preserve the explicit existing `sessionOverride` pointing to the prior child session file.

### Background single

Current:

```text
background -> detached async closure -> runSingleAgent(local, signal=undefined)
```

Target:

```text
background -> detached async closure -> common runner + resolved backend
```

Background cannot rely on the original tool call's AbortSignal after returning. Runtime execution must be registered under dispatch ownership so session shutdown/manual cancellation can address it separately.

### Chain

Current:

```text
for each step -> runSingleAgent(local)
```

Target:

```text
for each step -> common runner + resolved backend
```

Pass `step` and tracking identity so Herdr can keep/relabel a stable slot. Preserve `{previous}` substitution and stop-on-error semantics above the backend.

### Parallel

Current:

```text
mapWithConcurrencyLimit(4)
  -> executeOnce()
       -> cmux helper OR local helper
  -> optional one retry
```

Target:

```text
resolve batch runtime context/pool
mapWithConcurrencyLimit(4)
  -> common runner + backend
  -> optional one retry
```

Retry continues to be orchestration-owned. Backend receives a new attempt identity but may reuse the same Herdr pane slot.

### Foreground single

Current:

```text
cmux.splits ? cmux helper : local helper
```

Target:

```text
resolve backend -> common runner
```

## 9. Proposed implementation sequence for M2

Do not introduce HerdrBackend while local/cmux semantics are still duplicated. Suggested sequence:

1. add `backends/types.ts` with runtime execution evidence/callback contracts;
2. extract LocalBackend around the existing `spawn()` mechanics;
3. create the common `runSingleAgentWithBackend()` semantic runner;
4. migrate foreground single to common runner + LocalBackend only and prove parity;
5. migrate resume/background/chain/parallel to the same common runner while still using LocalBackend by default;
6. extract CmuxBackend from `runSingleAgentInCmuxSplit()`;
7. incorporate/revalidate the current cmux CLI fix branch;
8. remove `runSingleAgentInCmuxSplit()` and cmux-specific result parsing/fallback from `index.ts`;
9. add backend resolver/preparation interface;
10. only then implement HerdrBackend in M3/M4.

This sequence minimizes simultaneous semantic and runtime change.

## 10. Test gaps discovered

The current `src/resources/extensions/subagent/tests/` directory tests launch helpers, run store, model override, agent conflicts, and worktree cwd, but there is no obvious focused suite proving runtime-path parity across single/parallel/chain/background/resume.

Current cmux tests mostly exercise `CmuxClient`, layout logic, preferences, and stdio isolation rather than the duplicated subagent cmux execution pipeline.

M2 therefore needs new tests before/while extracting the runtime layer:

- deterministic fake GSD child fixture;
- local execution semantic snapshot/parity;
- mode-to-backend selection tests;
- resume/backend selection;
- background/backend ownership;
- parallel retry/backend reuse;
- cmux output relay/abort classification;
- no raw JSON pane mirror;
- phase-conflict consistency across backends;
- session-shutdown execution registry behavior.

## 11. Existing behavior intentionally not fixed inside pure extraction

To keep refactor reviewable, these should be separately tracked after parity baseline unless required for the abstraction itself:

1. chain mode ignoring the tool-level `isolated` option;
2. parallel retry recreating a fresh isolation environment per attempt;
3. worker-registry being parallel-only and ephemeral for five seconds;
4. any changes to `MAX_PARALLEL_TASKS=8` / `MAX_CONCURRENCY=4`;
5. user-facing cmux preference redesign.

The phase-conflict difference, abort/result inconsistency, raw JSON tee, and stale cmux CLI cannot be safely preserved as backend semantics; the abstraction should make these consistent or explicitly regression-test the corrected behavior.

## 12. M0.9 decision

**The proposed Local/Cmux/Herdr backend refactor is feasible and preferable to adding a third external execution function.**

The correct abstraction boundary is **below GSD single-child semantic preparation/result processing and above process/pane-specific execution**.

The primary M2 objective is therefore not "add Herdr". It is first to create a single authoritative child-execution semantic path, then plug Local/Cmux/Herdr runtimes into it.
