# P3.7 — Session-v4 live Herdr runbook

Date: 2026-09-03

Status: ready to execute; no live result recorded yet

## Purpose

Close the final session-v4 cutover gate through the public GSD subagent path:

```text
harness-v4 root session
→ public subagent tool
→ common semantic runner
→ HerdrBackend
→ real Herdr v0.8.2 worker pane
→ private JSON worker
→ durable artifacts
→ parent result and usage
```

This runbook does not authorize a default change. A failed or incomplete run
leaves `legacy-v3` as the default and does not rewrite either session format.

## Safety boundary

- Run only from an actual Herdr-managed root pane with `HERDR_ENV=1`.
- Use an isolated `GSD_HOME`, session directory, and evidence directory.
- Do not run from a child with `GSD_SUBAGENT_CHILD=1`.
- Do not attach to, close, or restart a Herdr session not created for this run.
- Keep `herdr.enabled=true` and `herdr.required=true`; no post-launch Local
  fallback is acceptable.
- Use the public `subagent` tool for every dispatch. A direct backend or private
  worker invocation is diagnostic evidence only and cannot pass this gate.
- Preserve failed, aborted, pane-loss, and orphan evidence. Do not clean it
  before the final review.

semantics attributable without storing or comparing arbitrary prose:

```text

```

For every normal worker, instruct it to return only its assigned marker. The
root must repeat the exact marker and report the subagent result/usage it
received; do not infer success from a worker pane becoming idle.

## Scenario order

### 1. Single

Ask the root to call public `subagent` in single mode with one installed agent
and return `P3V4_SINGLE_OK`. Verify:

- focus stays on the root pane;
- one `GSD Workers · <hash>` tab appears without stealing focus;
- one worker returns the exact marker through the common runner;
- parent usage is non-zero;
- the root session file begins with `{"kind":"header","version":4,...}`.

### 2. Affinity reuse

Ask the root to call public `subagent` in chain mode with two steps. Step one
returns `P3V4_AFFINITY_ONE`; step two must observe `{previous}` and return
`P3V4_AFFINITY_TWO`. Verify both ownership records contain the same
`affinityKey` and `paneId`, and the second `launch.json` is created only after
the first worker has published final exit/reporting evidence.

### 3. Parallel overflow

Ask the root for one public parallel dispatch containing five independent
tasks whose exact results are `P3V4_PARALLEL_1` through
`P3V4_PARALLEL_5`. Each task should stay active long enough to observe the
queue (for example, an allowed 10–20 second verification sleep before returning
its marker). Verify:

- at most four worker panes exist;
- exactly four children start before any slot settles;
- the fifth child's launch artifact appears only after a successful slot is
  reclaimable;
- all five exact results return once, with no duplicate artifact identity;
- parent usage equals the common runner's aggregate rather than pane metadata.

### 4. Cancellation

Start one long public single subagent whose tool launches a descendant process.
After its worker state is `working`, cancel the parent run once with the normal
root Ctrl-C path. Verify the backend targets that worker pane, the runner applies
bounded process-tree escalation, `exit.json` has `aborted=true`, no tracked
descendant remains, and the parent reports canonical `Subagent was aborted`.

Do not type Ctrl-C into an unrelated or UI-focused pane. Use the worker
identity from its ownership/state records when checking the result.

### 5. Pane loss and recovery

Start another long public single subagent. After `state.json` reports
`working`, close that exact worker pane through Herdr. Verify:

- `pane.get` loss becomes an explicit runtime error;
- the parent stops waiting within the backend's bounded probe window;
- the detached child and descendants are gone;
- failure evidence remains retained;
- no Local fallback or duplicate child appears.

Then run a new public single dispatch returning `P3V4_AFTER_PANE_LOSS_OK`.
It must recreate healthy capacity and complete normally.

### 6. Detach and reattach

While a bounded long worker is active, capture:

```bash
herdr api snapshot > "$GSD_P37_EVIDENCE/snapshots/10-before-detach.json"
```

Detach only the test client, wait for the worker to progress, reattach to the
same named test session, and capture:

```bash
herdr api snapshot > "$GSD_P37_EVIDENCE/snapshots/11-after-reattach.json"
```

The workspace/tab/pane public IDs and worker artifact identity must remain
stable, and no replacement dispatch may be created merely because the client
was absent.

### 7. Root process restart

After all active workers settle, copy `root.json` and the root v4 session file
to the evidence directory, exit GSD normally, and start the same candidate with
`--continue`. Capture the replacement `root.json` and session file again. The
session ID must stay the same, root instance ownership must change, prior
records must remain readable without rewrite, and a new public dispatch must
return `P3V4_AFTER_RESTART_OK` into the same v4 session.

This is a root-process restart test. A separate Herdr-server restart is not
required to re-prove completed M6 unless the topology or persistence behavior
differs during this run.

## Artifact review

Under `$GSD_HOME/runtime/herdr/v1/<root>/<dispatch>/<child>/`, review every
child:

- directory mode `0700`; regular artifact mode `0600`;
- `launch.json`, `stdout.jsonl`, `stderr.log`, `state.json`,
  `heartbeat.json`, `ownership.json`, and terminal `exit.json` when the runner
  survives long enough to publish it;
- `env.json` absent after its one-time read;
- identity fields match the containing path;
- successful children have `state=completed`, `ownership=settled`, exit 0,
  `aborted=false`, a final assistant marker, and non-zero usage;
- cancellation has `aborted=true`;
- pane loss is correlated with a missing pane in the captured topology and an
  explicit parent runtime error, not treated as success.

Capture each warm worker pane with `herdr pane read <id> --source
recent-unwrapped --lines 200`. Pane output may show bounded activity and
assistant text, but must not contain raw JSON event lines, token deltas, auth
values, or tool-result bodies.
